# 数据管理平台核心模块梳理

> 本文档梳理数据管理平台三个核心模块（数据管理模块、数据开发模块、项目管理模块）的核心功能及关联关系。

---

## 一、模块总览

| 模块         | 目录                            | 定位                                                         |
| ------------ | ------------------------------- | ------------------------------------------------------------ |
| 数据管理模块 | `src/pages/theme-management`    | 以"一级主题"为维度，管理业务主题及报送属性                   |
| 数据开发模块 | `src/pages/data-dev-spec`       | 以"数据块/报文/报表"为维度，管理业务口径与技术口径全生命周期 |
| 项目管理模块 | `src/pages/projects-management` | 以"项目"为维度，关联口径与规则，驱动检视与投产流程           |

三者共同构成"主题 → 数据块口径 → 项目实施"的数据治理链路。

---

## 二、数据管理模块（theme-management）

### 2.1 模块定位

面向数据治理管理人员，维护"一级主题"维度的元数据，是数据开发模块的上游分类维度。

### 2.2 目录结构

```
theme-management/
├── theme-list/            # 主题列表
└── ThemeFormModal/        # 主题新增/修改弹窗
```

### 2.3 核心功能

#### 主题列表（theme-list/index.tsx）

- **查询能力**：支持按一级主题名称、主题负责人、业务负责人、开发小组、是否监管类、报送对象、报送类型、业务类型、产品类型等多维度筛选。
- **列表展示**：展示主题名称、主题/业务负责人、业务类型、是否监管类、报送对象/类型、产品类型、报表/报文/数据块数量、关联系统、展示端等字段。
- **主题入口**：点击主题名称可跳转至数据开发模块，并携带 `themeId` 作为筛选条件：
  ```ts
  navigate(`/themes/data-dev-spec?pageSource=theme&themeId=${record.themeId}`);
  ```
- **操作能力**：新增一级主题、修改主题信息。

#### 主题表单（ThemeFormModal/index.tsx）

- **新增/修改**：通过同一弹窗复用，依据 `themeId` 判断行为。
- **表单字段**：
  - 一级主题名称（必填，最多 30 字符）
  - 是否监管类（必填，编辑时不可改）
  - 报送对象（监管类时必填，编辑时不可改）
  - 报送类型、业务类型（必填，编辑时不可改）
  - 主题负责人、业务负责人（多选，必填）
  - 关联系统、展示端（多选）
- **提交处理**：多选人员字段以逗号拼接后提交。

### 2.4 关键数据模型

- 实体：`ThemeInfo`
- 关键字段：`themeId`、`themeName`、`developHead`、`businessHead`、`supervision`、`reportTarget`、`reportType`、`businessType`、`productType`、`relatedSystem`、`displayPlatform`、`dataAmount`

## 三、数据开发模块（data-dev-spec）

### 3.1 模块定位

面向数据开发与业务人员，围绕"数据块/报文/报表"维护业务口径与技术口径，覆盖新增、详情、编辑、流程处理、技术口径、问题反馈、监测等全生命周期。

### 3.2 目录结构

```
data-dev-spec/
├── DataDevSpecList/         # 数据块列表
├── DataDevSpecAdd/          # 新增数据块
├── DataDevSpecDetail/       # 口径详情/版本对比/同步口径
├── DataDevSpecEdit/         # 业务口径编辑
├── DataDevSpecOperate/      # 口径流程处理（澄清/取数/开发/验收/投产）
├── DataDevSpecIt/           # 技术口径维护与技术检视
├── DataDevSpecIssueList/    # 口径/数据问题反馈管理
└── DataDevSpecMonitor/      # 规则配置与监测结果
```

### 3.3 核心功能

#### 3.3.1 数据块列表（DataDevSpecList）

- **筛选维度**：一级主题、接口表、数据块 ID/名称、业务部门、业务/开发负责人、状态、口径状态、是否监管类、报送类型、产品类型、开发小组、创建时间倒序、与我相关等。
- **列表展示**：主题、接口表、数据块 ID/名称、产品类型、业务部门、业务/开发负责人、状态、报送类型、最新版本、最新技术口径版本、各阶段版本（已澄清/取数/验证/开发/验收/投产）等。
- **操作能力**：
  - 基础信息修改（`ModifyBlockFormModal`）
  - 口径维护（跳转详情）
  - 流程处理（跳转 `operate`）
  - 数据验证（仅"一表通"系列主题展示）
  - 监测（跳转 `monitor`）
  - 口径对比（最多选 2 条，`DataBlockSpecCompareDrawer`）
  - 问题反馈管理（口径问题/数据问题）
  - 导出（`SpecExportBtnGroup`）
  - 新增数据块
- **主题联动**：支持通过 URL 携带 `themeId` 自动筛选并提交查询。

#### 3.3.2 新增数据块（DataDevSpecAdd）

- 表单基于 `AddBlockFormItems`，支持选择主题、填写数据块基础信息与业务口径要素。
- 支持通过 `UploadBusinessModal` 导入业务口径要素。
- 提供"保存"（`createDataBlock`）与"提交"（`submitDataBlock`）两种动作。
- 当报送类型非"数据块"时，`dataBlockId` 自动取 `dataBlockName`。
- 兼容沙盒（小算手）环境，携带 `reportId` 调用报表专用接口。

#### 3.3.3 口径详情（DataDevSpecDetail）

- 展示基础信息与业务口径信息（版本、状态、附件、范围、数据粒度、业务要素、版本说明、各阶段人员与时间）。
- **版本对比**：`SpecCompareDrawer` 支持业务口径版本差异对比。
- **技术口径**：通过抽屉 `DataDevSpecIt` 查看/维护技术口径。
- **同步口径**：可选择业务要素同步至其他数据块，流程为"选要素 → 选数据块 → 填变更说明 → 调用 `batchUpdateElement`"。
- **修改业务口径**：跳转编辑页，支持沙盒与正常两种路径。
- 面包屑支持来自项目管理的回跳（`pageFrom=project`）。

#### 3.3.4 业务口径编辑（DataDevSpecEdit）

- 基于历史版本加载数据，可切换版本号回填表单。
- 支持导入业务口径要素（`UploadBusinessModal`）。
- 提供"保存为草稿"（`createDataBlockSpec`）与"提交"（`submitDataBlockSpec`）两种动作。
- 提交时需填写变更说明（`RemarksModal`），并自动生成变更日志。
- 校验要素不能为空、不能重复。

#### 3.3.5 流程处理（DataDevSpecOperate）

- 按口径状态（20/30/40/50/60/70）驱动"完成澄清/取数/验证/开发/验收/投产"按钮。
- 高级用户（`specification_opr` 字典配置）可一次性看到全部高级操作按钮。
- 调用 `reviewDataBlockSpec` 推进状态。

#### 3.3.6 技术口径（DataDevSpecIt）

- 以抽屉形式展示，支持版本切换、查看与编辑两种模式。
- **查看模式**：展示技术信息、范围、要素技术口径；支持技术口径导出、修改入口、技术检视入口。
- **编辑模式**：支持复制上个版本技术口径、导入技术口径要素（`UploadItModal`）、提交（`submitDataBlockSpecIt`）。
- **技术检视**：`TechReview` 展示技术检视问题列表，关联问题反馈模块。
- 操作按钮通过 `useSpecItAction` 根据状态与未解决问题数量动态渲染。

#### 3.3.7 问题反馈（DataDevSpecIssueList）

- 按 `type`（口径问题/数据问题）区分列表。
- 支持按主题、接口表、数据块、版本、提出人、处理人、问题状态、问题描述等筛选。
- 操作：处理问题、转处理人、查看口径、修改问题、添加问题、导出。
- 默认仅显示本人待处理任务，可通过"全量"查看其他任务。

#### 3.3.8 监测（DataDevSpecMonitor）

- 通过 Tabs 切换"规则配置"与"监测结果"。
- 规则配置（`RuleConfig`）：支持新增/编辑规则、要素选择、要素文本域配置。
- 监测结果（`DataQuanlity`）：展示数据质量监测结果。

### 3.4 关键数据模型

- `DataBlockRecord` / `DataBlockSpecRecord` / `DataBlockSpecElementRecord`（来自 `src/types/dataBlock`）
- 关键字段：`dataBlockId`、`themeId`、`interfaceTable`、`dataBlockName`、`version`、`status`、`elementDTOList`、`itTable`、`itTask`、`devStatus` 等

## 四、项目管理模块（projects-management）

### 4.1 模块定位

面向项目管理人员与检视人员，以项目为单位关联数据块口径与质量规则，驱动口径/代码检视与投产流程。

### 4.2 目录结构

```
projects-management/
├── index.tsx                       # 项目列表
├── components/
│   ├── ProjectFormModal.tsx        # 新增/修改项目
│   ├── EditProjNoModal.tsx         # 更新项目编号
│   ├── UploadImportModal.tsx       # 关联口径选择
│   ├── ProjAssRuleDrawer.tsx       # 关联规则抽屉
│   ├── ProjectDisplay.tsx
│   └── BatchDevStatusModal/        # 批量处理技术开发状态
├── hooks/
│   └── useActionProjectSpec.ts     # 项目口径流程操作
├── project-detail/                 # 项目详情（基础信息/关联口径/关联规则）
└── projects-process/               # 项目流程处理（项目口径/项目规则）
```

### 4.3 核心功能

#### 4.3.1 项目列表（index.tsx）

- **筛选维度**：项目编号、项目名称、项目负责人、负责人小组、项目状态、数据块/报文/报表名称、起止时间、与我相关。
- **列表展示**：项目编号、名称、负责人、状态、口径/代码检视日期、项目简述/备注、功能点、检视人、创建人/时间。
- **操作能力**：
  - 详情（跳转 `project-detail`）
  - 修改（`ProjectFormModal`）
  - 操作（跳转 `projects-process`，并清空口径/规则参数）
  - 更新编号（`EditProjNoModal`）
  - 删除（`deleteProject`）
  - 批量导出口径规格（`exportProjectSpecification`）
  - 导出项目列表（`exportProjectList`）
  - 新增项目

#### 4.3.2 项目表单（ProjectFormModal.tsx）
- 字段：项目编号（新增后不可改）、项目名称、功能点、负责人（多选）、检视人、口径/代码检视截止日期、项目描述、项目备注。
- 新增时默认 `projectState='10'`。

#### 4.3.3 项目详情（project-detail）

- 顶部展示项目名称、状态、描述、功能点。
- Tabs 页签：
  - **基础信息**（`ProjBaseInfo`）
  - **关联口径**（`RelatedSpec`）：查询项目关联的口径列表，支持关联/取消关联、导出、版本对比。
  - **关联规则**（`RelatedRule`）：查询项目关联的质量规则，支持关联/取消关联、导出、查看规则详情（`RuleDetailModal`）。

#### 4.3.4 项目流程处理（projects-process）

- 通过 Tabs 切换"项目口径"与"项目规则"。

##### 项目口径（ProjectAssSpec）

- 查询项目下的口径列表（`getFormatSpecificationList`），支持多维度筛选。
- 操作：
  - 明细：跳转数据开发模块口径详情（携带 `pageFrom=project` 与 `prePath`）
    ```ts
    navigate(`/themes/data-dev-spec/detail?id=${dataBlockId}&pageFrom=project&prePath=...`);
    ```
  - 版本对比（`SpecCompareDrawer`）
  - 口径对比（`DataBlockSpecCompareDrawer`，选 2 条）
  - 批量处理技术开发状态（`BatchDevStatusModal`）
  - 关联口径 / 取消关联（`batchUpload` / `batchCancelUpload`）
  - 导出（`exportSpecificationList`）
  - 流程操作（`useActionProjectSpec`）：完成澄清/开发/验收/投产，受部门权限控制（仅信息技术部可见全部按钮，其他部门仅见"完成验收"）

##### 项目规则（ProjectAssRule）

- 查询项目关联规则（`projectRuleListByPost`）。
- 操作：关联规则（`ProjAssRuleDrawer`）、取消关联（`projectCancelBatchAssRuleByPost`）、导出（`exportProjectRuleList`）。
- 同一 `ruleId` 多版本时仅允许选择一条，通过 `getCheckboxProps` 禁用其他版本。

#### 4.3.5 批量处理技术开发状态（BatchDevStatusModal）

- 按 `devStatus` 分组展示选中数据。
- 状态流转：初始/00 → 10（口径可检视）→ 20（技术口径验收通过）→ 30（代码可检视）→ 40（代码验收通过）。
- 权限校验：状态 10、30 需当前用户为项目检视人（`projectReviewUser`）。
- 代码可检视操作（20→30）需填写"检视版本信息"。

### 4.4 关键数据模型

- `DataProject`（项目）、`UploadAndProcessRecord`（项目口径关联）、`DmCheckConfigManageDTO`（规则）
- 关键字段：`projectNo`、`projectName`、`projectManager`、`reviewUser`、`projectState`、`detailDeadline`、`codeDeadline`、`funPoints`、`dataBlockId`、`version`、`devStatus`、`ruleId`

## 五、三模块关联关系

### 5.1 数据流向概览

```
┌──────────────────────┐
│  数据管理模块         │
│  (theme-management)  │
│  一级主题元数据       │
└──────────┬───────────┘
           │ themeId 作为分类维度
           ▼
┌──────────────────────┐
│  数据开发模块         │
│  (data-dev-spec)     │
│  数据块/口径/技术口径 │
└──────────┬───────────┘
           │ dataBlockId / version 作为实施对象
           ▼
┌──────────────────────┐
│  项目管理模块         │
│  (projects-management)│
│  关联口径与规则、驱动检视/投产 │
└──────────────────────┘
```

### 5.2 详细关联点

#### 5.2.1 数据管理 → 数据开发

- **主题筛选联动**：数据管理列表点击主题名称，跳转数据开发列表并携带 `themeId`，自动按主题筛选数据块。
- **主题属性透传**：主题的报送类型、是否监管类、产品类型等属性在数据开发模块中作为筛选条件与展示字段复用（如 `supervision`、`reportType`、`productType`）。
- **主题配置消费**：数据开发新增/编辑时通过 `useThemeConfig(themeId)` 获取当前主题配置（如 `reportType`、`reportTypeName`、`interfaceRequire`），影响表单行为（如 `dataBlockId` 自动赋值逻辑、接口表加载）。

#### 5.2.2 数据开发 → 项目管理
- **口径关联**：项目管理通过 `UploadImportModal` 选择数据块口径，调用 `batchUpload` 将口径关联到项目；关联后可在项目口径列表/项目详情中查看。
- **口径明细回跳**：项目口径列表"明细"按钮跳转数据开发口径详情页，携带 `pageFrom=project` 与 `prePath`，详情页/编辑页据此渲染面包屑并支持返回项目流程页。
- **版本对比复用**：项目口径列表与项目详情均复用数据开发的 `SpecCompareDrawer`、`DataBlockSpecCompareDrawer` 进行版本/口径对比。
- **技术开发状态联动**：项目口径列表展示 `devStatus`（技术口径状态），并通过 `BatchDevStatusModal` 调用 `batchOperateSpecItStatus` 批量推进技术口径状态，与数据开发模块的技术口径状态保持一致。
- **流程操作复用**：项目口径的流程操作（完成澄清/开发/验收/投产）与数据开发模块的 `DataDevSpecOperate` 共享同一套状态码（CQ/KF/YS/TC），项目管理侧通过 `operateProject` 批量驱动所选口径。

#### 5.2.3 数据管理 → 项目管理（间接）

- 项目口径列表/项目详情中展示"一级主题"字段（`themeName`），其来源为数据块所属主题，即项目管理通过数据开发口径间接关联到数据管理主题。
- 项目规则列表同样展示"一级主题"、"报表/接口表"、"数据块 ID/名称"等字段，体现规则与主题/数据块的间接关联。

### 5.3 状态流转对照

| 阶段      | 数据开发口径状态（status） | 技术口径状态（devStatus）              | 项目流程操作                 |
| --------- | -------------------------- | -------------------------------------- | ---------------------------- |
| 初始      | 10（口径待检视）           | 00/空                                  | —                            |
| 澄清      | 20 → 完成澄清(CQ)          | —                                      | 完成澄清(CQ)                 |
| 取数/验证 | 30/40（注释中保留）        | —                                      | （流程精简，当前主流程跳过） |
| 开发      | 50 → 完成开发(KF)          | 10→20（口径可检视 → 技术口径验收通过） | 完成开发(KF)                 |
| 代码检视  | —                          | 20→30（代码可检视，需检视人+版本信息） | —                            |
| 验收      | 60 → 完成验收(YS)          | 30→40（代码验收通过）                  | 完成验收(YS)                 |
| 投产      | 70 → 完成投产(TC)          | —                                      | 完成投产(TC)                 |

> 说明：数据开发模块 `DataDevSpecOperate` 中保留取数(QS)/验证(YZ)按钮但已注释，主流程为"澄清 → 开发 → 验收 → 投产"；项目流程处理同步精简。技术口径状态由 `BatchDevStatusModal` 单独驱动，与口径状态协同推进。

### 5.4 共享组件与依赖

| 共享资源                     | 使用方                           | 说明                        |
| ---------------------------- | -------------------------------- | --------------------------- |
| `SpecCompareDrawer`          | 数据开发详情、项目口径、项目详情 | 业务口径版本对比            |
| `DataBlockSpecCompareDrawer` | 数据开发列表、项目口径           | 两条数据块口径对比          |
| `UploadImportModal`          | 项目流程、项目详情               | 选择并关联口径              |
| `ProjAssRuleDrawer`          | 项目流程、项目详情               | 选择并关联规则              |
| `DEV_STATUS_MAP`             | 数据开发技术口径、项目口径列定义 | 技术口径状态色值/文案       |
| `useThemeConfig`             | 数据开发新增/编辑、问题反馈      | 根据 `themeId` 获取主题配置 |
| `useParamsStore`             | 三个模块列表页                   | 持久化查询参数              |

## 六、总结

- **数据管理模块**是分类与元数据的起点，定义"主题"维度及其报送属性。
- **数据开发模块**是核心生产能力，围绕数据块维护业务/技术口径，并提供问题反馈与监测能力。
- **项目管理模块**是交付与检视的组织层，通过关联口径与规则，驱动跨数据块的批量检视与投产流程。

三者通过 `themeId`、`dataBlockId`、`version`、`projectNo` 等关键标识串联，形成"主题分类 → 口径生产 → 项目交付"的闭环。
