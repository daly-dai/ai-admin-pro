# 数据管理平台 · 核心数据模型

> 回答框架第四章的核心实体及关系。配套文档：功能、主流程、三问、平台定位。

## 实体关系图

```
主题 Theme (themeId, 报送属性…)
  │ 1
  │ 包含
  ▼ N
数据块 DataBlock (dataBlockId, themeId, interfaceTable)
  │ 1
  ├── 拥有 ──► 业务口径 DataBlockSpec (version, status)
  │                 │ 1─N
  │                 └─► 业务要素 Element
  │
  └── 拥有 ──► 技术口径 DataBlockSpecIt (version, devStatus, itTable, itTask)
                    │ 1─N
                    └─► 要素技术口径

项目 Project (projectNo, projectState)
  ├── N:M ──► 数据块口径 (via UploadAndProcessRecord, 关联 dataBlockId + version)
  └── N:M ──► 规则 Rule (ruleId)
```

## 三个关键设计点

1. **「口径」是版本序列，不是单条记录。** 业务口径、技术口径都带 `version`，所以「改口径」=「新增版本」，这是「可追溯」的技术根基。
2. **项目「关联」口径，不「拥有」口径。** 通过 `UploadAndProcessRecord` 关联 `(dataBlockId, version)`。口径是资产，项目是批次——同一口径可独立存在，也可在不同时间被不同项目关联。
3. **规则是独立实体。** 质量规则（Rule）单独管理，项目只「关联」它，不「定义」它。

## 版本管理

- 业务口径版本：每次变更提交产生新版本，填变更说明 + 自动生成变更日志。
- 技术口径版本：独立记版本，可「复制上个版本」再改。
- 两者各自独立，互不影响。
