# 数据管理平台 · 通用设计 vs 公司特例

> 抽象的本质：把「通用设计」和「公司特例」剥离开。本文档是平台抽象的产物。

## 对照表

| 项目 | 现状（公司特例 / 遗留） | 通用设计（抽象后） |
| --- | --- | --- |
| 项目立项 | 立项在公司统一项目申请平台，本平台只登记 | 平台内直接「项目申请 → 立项 → 走流程」，闭环 |
| 一表通 + 数据验证 | 仅「一表通」系列主题有数据验证 | 数据验证能力应普适，或作为主题级可选能力 |
| 取数(30)/验证(40) 状态码 | 代码保留但已精简，主流程跳过 | 主流程收敛为「澄清 → 开发 → 验收 → 投产」 |
| 沙盒（小算手）+ reportId | 环境适配，走报表专用接口 | 抽象为「多环境适配层」，而非硬编码分支 |
| 部门权限（仅信息技术部见全部按钮） | 绑定具体部门「信息技术部」 | 抽象为「角色权限」：技术角色 vs 业务角色，不绑死部门名 |
| 数据块/报文/报表 | 三种报送类型（待确认业务含义） | 抽象为「交付场景类型」枚举 |

## 抽象版平台定义

把公司特例剥离后，这个平台可以这样描述：

> **一个企业级数据口径管理平台**：以主题为分类骨架，管理「业务口径 + 技术口径」的全生命周期（含版本），通过「项目」批次驱动检视与投产流程，使每一次口径变更**可追溯、可审计、可控制**，保障下游数据可信。

这正是它「有普适性、有代表性」的原因——它的骨架是通用的数据治理模式，公司特例只是套在上面的皮。
